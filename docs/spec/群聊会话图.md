## 1. 为什么需要

### 1.1 症状

- 两个人交替刷同一句辱骂：`隐身人` 连发 3 条「@雷霆大肥鱼 fw」，`AMelax` 连发 2 条「@雷霆大肥鱼 废物」。bot 回复把两人的次数合并成「第四遍 / 第五遍」，被质疑「你分得清谁是谁不」后进一步自我推翻成「我以为重复是另一个人，是我笨」。
- 群友问「谁钓了几斤」，bot 答「**你**上周钓了五斤二两」——把别人的事安到发问者头上。
- 话题里出现「他 / 她 / 你们」时，无法判断指 bot、指某个群友，还是泛指群里。

### 1.2 根因

| 层 | 问题 |
|---|---|
| 落库 | `messages` 只存正文，不存「谁说的」；历史窗口里只有一串裸文本 |
| 模型输入 | 原方案靠 OpenAI 兼容接口的 `name` 字段（`qq_bot/ai/openai_client.py` 设置 `msg["name"] = sender_name`）。实测 DeepSeek 官方 API 直接忽略 `name`：两个发送者各带 `name`，问「谁钓了几斤」→ 3 次全部答「你上周钓了五斤二两」 |
| 计数 | 次数、人数这类聚合交给模型自己数，长窗口必错；被质疑时还会顺着质疑改口 |
| 指向 | 没有把「这条在跟谁说话」显式化，@ 别人、双人对话、bot 后的追问都靠模型猜 |

### 1.3 结论

1. 身份必须写进 prompt 正文，**逐条**，不能依赖 `name` 字段。
2. 归属和计数由代码算，模型只负责表达；不给模型「自己数」的机会。
3. 「这条指向谁」是代码能判的，判完直接决定回不回应，而不是让模型猜。

## 2. 当前实现（P1：会话图 + 逐条身份标签）

### 2.1 会话图（`qq_bot/chat/conversation.py`）

纯内存，按群一份，**不落库**；每个群在进程内第一次出现时，从 `messages` 表回填最近 30 条（P3-a），之后只增量 `observe`。

| 对象 | 职责 |
|---|---|
| `MessageNode` | 单条消息：`mid`、`sender_id`、`sender_name`、`text`、`at`、`mentions`、`mention_bot`、`reply_to`、`tokens`（字符二元组） |
| `SpeakerStat` / `SpeakerLedger` | 每人发言次数、高频文本 Counter、最后发言时间；`observe` / `stats` / `count_of` / `name_of` / `who_said` |
| `GroupConversation` | 最近 30 条 `MessageNode`、账本、`bot_id`、bot 最近发言时间与文本、`bot_mids`；`observe` / `note_bot` / `prev_speaker` / `resolve` / `topic_relevant` |
| `ConversationManager` | 按 `group_key` 维护 `GroupConversation`，LRU 上限 512；`observe` / `note_bot` / `addressee` / `topic_relevant` / `count_of` / `needs_rebuild` / `mark_rebuilt` / `rebuild` / `reset` |

文本归一化：NFKC、全角转半角、小写、压空白；bot 名字从 `GROUP_PRESENCE_KEYWORDS` 解析（`parse_bot_names`）。

### 2.2 逐条身份标签

`qq_bot/chat/turn.py::_annotate_history` 在组装 prompt 时给群历史消息加前缀：

```text
<user identity name="小明" id="U1"/>
今天在河边钓了条三斤的鲤鱼
```

P3-d 起标签带 `sender_id`；`sender_id` 为空时退回 `<user identity name="小明"/>`。

规则：

- 仅群聊；仅 `role=user`；`content` 非空。
- 已以 `<user identity` 开头的（例如视频链路先落库的消息）不重复加。
- `sender_name` 为空时用「某成员」。
- **只改发给模型的 prompt，不回写数据库**。
- 当前这条消息另用完整标签：`<user identity id="..." name="..." call="..."/>`（含 id，`call` 是群名片/昵称）。

效果对比（同一组消息、真实模型）：

| 方式 | 问「谁钓了几斤」的回答 |
|---|---|
| 旧：`name` 字段 | 「**你**上周钓了五斤二两」 |
| 新：正文标签 | 「**小明**钓了三斤，**阿强**钓了五斤二两」 |

### 2.3 指向解析（`GroupConversation.resolve`）

输入最近一条消息，输出 `Addressee(target, score, evidence)`；`target` 为 `"bot"`、某个 openid，或 `"group"`。取最高分，同分按下列优先级（rank 小的优先）。0.90 这条可用 `GROUP_PRESENCE_POLICY_FORCE_SCORE` 覆盖（P3-c），其余阈值暂固定：

| # | 信号 | 分数 | 指向 |
|---|---|---|---|
| 0 | `@bot` | 1.00 | bot |
| 1 | 引用了 bot 的消息 | 0.92 | bot |
| 2 | 正文里是名字的 `CALL`（「大肥鱼 在吗」） | 0.90 | bot |
| 3 | `@` 了某个群友 | 1.00 | 该群友 |
| 4 | 「你 / 你们」且 bot 是上一句发言者 | 0.75 | bot |
| 5 | bot 刚说完、这句以问号结尾 | 0.60 | bot |
| 5 | bot 刚说完 120 秒内、这句带疑问词（什么/怎么/为什么/哪/谁/几/多少/吗/呢） | 0.65 | bot |
| 4 | bot 刚问完「咋了/怎么了/在吗/你说/说吧」之类，120 秒内的下一句 | 0.80 | bot |
| 6 | 双人交替对话（A→B→A） | 0.80 | 对话另一人 |
| — | 以上都没有 | 0.20 | group |

### 2.4 话题相关性

`GroupConversation.topic_relevant(node, window=5, min_overlap=2)`：当前消息与 bot 上一句、或最近 5 条消息，字符二元组重叠 ≥ 2 即算相关。只用于参与策略（§3），不注入 prompt。

## 3. 参与策略（P2：`qq_bot/chat/participation.py`）

在 judge 之前、抽奖之前先做一道确定性判断：

| 条件 | 动作 | reason |
|---|---|---|
| 没有会话上下文 | 交回 presence（正常抽奖） | `no_context` |
| 指向 bot 且 score ≥ 0.90 | **必回**（`force`，跳过抽奖与 `REPLY_COOLDOWN`） | `target_bot` |
| 指向 bot 且 score 0.60–0.75 | 交回 presence（灰度） | `bot_gray` |
| 指向某个群友 | 不回（AWAKE 中则累计一次 PASS） | `target_other_user` |
| 指向 group 且话题相关 | 交回 presence（正常抽奖） | `topic_relevant` |
| 指向 group 且话题无关 | 不回 | `topic_irrelevant` |

- 策略 `PASS`（这条不是对 bot 说的）只跳过，**不累计 `PASS_LIMIT`**、也不重置 `REPLY_COOLDOWN`；只有 judge 的 `PASS` 才累计，连续 3 次关窗。
- 0.65 的「追问」落进 gray 带，交给窗口内 judge 决定，不会被策略直接 PASS 掉。
- `force` 唤醒在 `SLEEPING` 下忽略 `WAKE_COOLDOWN`，但仍受日上限约束；这是「叫名字就进窗」的实现。
- 关键词路径（`keyword_awake`）优先级高于策略：窗口内叫名字永远 `force`。
- 整体回退：`GROUP_PRESENCE_POLICY_ENABLED=false`。
- 日志：`presence policy group=<gid> target=<bot|openid|group> score=<s> action=<reply|pass|presence> reason=<r>`。

## 4. 已移除：`[群聊状态]` 注入（v4）

v3 曾在每条回复的 prompt 里注入一行 `[群聊状态] 最近 10 分钟：…`。v4 起移除，原因：

- 逐条 `<user identity>` 标签已经解决归属；再由代码汇总一行，属于重复表达，还占 ~30–50 token。
- 汇总行里的「名字×次数」和逐条标签可能不一致（改名、窗口差异），反而制造矛盾。
- 用户明确要求「`[群聊状态]` 部分不用保留，如果加入了就删除，没加入就不要在添加了」。

同步删除：`SystemPromptParts.state`、`conversation.render/_target_name`、6 个 `GROUP_CONVERSATION_*` 参数、`system.md` 里的「以 `[群聊状态]` 为准」。**会话图本身保留**，只服务 P2 策略。

## 5. 集成点

| 位置 | 做什么 |
|---|---|
| `qq_bot/plugins/qqbot_official/__init__.py` | 群消息入口（@ 路径 `_dispatch`、非 @ 路径 `handle_full_message`）都调 `conversation.manager.observe(...)`；`_event_mentions` 解析 `mention_user / mention / at` 段 |
| 同上 | 被动回复成功后 `note_bot(gid, body)`，让「上一句是 bot」可判 |
| `qq_bot/chat/autotrigger.py` | 自动接话成功后 `note_bot`（文本、复读、ABOUT 过渡句都记） |
| `qq_bot/chat/turn.py` | `_annotate_history` 加逐条标签；当前消息用完整 identity 标签 |
| `qq_bot/chat/autotrigger.py` | keyword → `participation.decide` → judge → `presence.observe_active` |
| `qq_bot/chat/presence.py` | `policy_pass` 直接跳过（不计数）、`forced_wake` |
| `qq_bot/plugins/qqbot_official/__init__.py` | `_rebuild_conversation`：本群首条消息时从 `messages` 回填；失败只记日志 |

## 6. 配置

| 键 | 默认 | 说明 |
|---|---|---|

## 9. 已知限制

- 重启后会话图由数据库回填（本群首条消息触发一次查询），但只回填最近 30 条；更早的计数仍会丢。
- 历史标签已带 `sender_id`，但 id 为空的旧消息只有名字；同名仍可能串人。
- 只有强制回复阈值（0.90）可配；0.80 / 0.75 / 0.60 仍固定，未按群校准。
- 「引用 bot」信号（0.92）解析逻辑已支持，但生产链路暂未把消息的 `reply_to` 与 bot 的 `bot_mids` 接进会话图，当前不会触发；需要时补 `Incoming.reply_to` 与回复 msg_id 回填。
- 只保留最近 30 条，跨 10 分钟窗口的计数会丢；对「10 分钟内谁说了几次」够用。
- 每消息 O(30) 的二元组计算，开销可忽略；不额外调模型。
