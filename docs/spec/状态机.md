# 群聊存在感状态机（现状整理）

> 对应代码：`qq_bot/chat/presence.py`、`qq_bot/chat/autotrigger.py`、`qq_bot/chat/judge.py`
> 参数来源：`.env` 的 `GROUP_PRESENCE_*`（本文最后一节是当前快照）
> 适用版本：P1 + P2 + P3（judge 已启用）

## 1. 一句话

三个状态：`SLEEPING`（不在场）、`AWAKE`（这 10 分钟在场）、`MUTED`（被要求闭嘴 30 分钟）。
所有"要不要说话"的判定都发生在状态转移和抽奖上；状态本身只记"在不在场"。

```
                   ④ @bot + 静默词
      ┌────────────────────────────────────┐
      │                                    ▼
 ┌────────────┐   ⑤ 到期 / ⑥ 别的 @bot   ┌────────────┐
 │  SLEEPING  │ ◀─────────────────────── │   MUTED    │
 │  不在场     │                          │  闭嘴 30 分 │
 └────────────┘                          └────────────┘
      │  ▲
      │  │  ⑦~⑫ 任意 _close(reason)
      │  │  → 唤醒冷却 300s
      │  └───────────────────────────────┐
      │                                  │
      │ ① 普通消息抽奖命中（p=0.6）       │
      │ ② 名字 CALL（窗口 600s）          │
      │ ③ 名字 ABOUT（窗口 300s+hook）    │
      ▼                                  │
 ┌────────────┐                          │
 │   AWAKE    │ ─────────────────────────┘
 │  在场 10 分 │
 └────────────┘
      │
      │ 窗口内 0-1 命中（p = 0.6 × 1.6 ≈ 0.96）
      ▼
   发一条（受 3s 发言冷却、120 条/日上限约束）
```

## 2. 一条群消息怎么走

平台层先分流：带 @ 的走被动通道，不带的走"存在感"通道。

```
收到群消息
│
├── 消息 @ 了 bot ──────────────────────────────┐
│                                              │
│   passive_window 登记（平台 5 分钟/5 次）      │
│   observe_passive()                          │
│     ├─ 含静默词（闭嘴/别说了/安静）            │
│     │    → MUTED 30 分钟，回一个「好」         │
│     ├─ 当前 MUTED 且不是触发静默的那条         │
│     │    → 解除静默，正常回复                  │
│     ├─ 当前 MUTED 且正是触发静默的那条 ack     │
│     │    → 不解静默，也不重复回                │
│     └─ 其他 → 正常回复（不影响 AWAKE 窗口）    │
│                                              │
└── 没有 @ bot ─────────────────────────────────┤
                                               │
    文本里出现「大肥鱼」？                      │
      ├─ 是 → relevance 分类                    │
      │    ├─ HOMONYM（鱼/菜/价格）→ 丢弃      │
      │    ├─ CALL（在吗/叫你）→ AWAKE 600s     │
      │    └─ ABOUT（议论）→ AWAKE 300s + hook  │
      │                                        │
      └─ 否 → observe_active()                 │
             ├─ 硬闸门（任一不过就丢弃）         │
             │   窗口到期 / MUTED / 黑名单 /      │
             │   主动权限关闭 / 重复 id /         │
             │   不可接（空、纯表情、纯链接、命令）│
             ├─ hook 生效 → 接一句（不改状态）    │
             ├─ 复读命中 → 复读（不改状态）       │
             └─ 按状态分流                       │
                  ├─ AWAKE → judge 三态判定       │
                  │    ├─ SLEEP → 关窗            │
                  │    ├─ PASS  → 记一次，留在窗口 │
                  │    └─ REPLY → 窗口抽奖 p≈0.96 │
                  └─ SLEEPING → 唤醒抽奖 p=0.6    │
                       ├─ 命中 → 进 AWAKE，发言   │
                       └─ 没中 → 丢弃             │
```

## 3. 状态转移表

| # | 从 | 触发 | 到 | 副作用 |
|---|---|---|---|---|
| ① | SLEEPING | 普通消息，唤醒抽奖命中（p=0.6） | AWAKE | `expires_at = now + 600`，发一条 |
| ② | SLEEPING | 名字分类 CALL | AWAKE | `expires_at = now + 600`，立即回一条 |
| ③ | SLEEPING | 名字分类 ABOUT | AWAKE | `expires_at = now + 300`，开 hook 120s，回过渡句 |
| ④ | 任意 | @bot 且文本含静默词 | MUTED | `mute_until = now + 1800`，回「好」 |
| ⑤ | MUTED | 静默到期 | SLEEPING | 清空静默字段，无冷却 |
| ⑥ | MUTED | 别的 @bot | SLEEPING | 那条正常回；只有"再被 @"能解 |
| ⑦ | AWAKE | 窗口到期 | SLEEPING | `_close("timeout")` → 唤醒冷却 300s |
| ⑧ | AWAKE | 消息 @ 了别人 | SLEEPING | `_close("mention_other")` |
| ⑨ | AWAKE | judge 判 SLEEP | SLEEPING | `_close("model_left")` |
| ⑩ | AWAKE | judge 连续 3 次 PASS（策略 PASS 不计） | SLEEPING | `_close("pass_limit")`；发言成功清零 |
| ⑪ | AWAKE | 当日主动条数 ≥ 120 | SLEEPING | `_close("daily_cap")` |
| ⑫ | AWAKE | 主动消息发送失败 | SLEEPING | 40034105 禁主动；429 → 60s；其他 30s |

补充规则：

- **@ 不改变 AWAKE 窗口**：被 @ 只是回一条，窗口按原 `expires_at` 到期。
- **窗口内再喊名字**不会再开窗，交回 0-1 但强制必回（`force`）。
- **复读、hook 接话**都不改状态，也不算进 `REPLY_COOLDOWN`；复读计入日上限。
- **重启**后窗口、静默、冷却全部丢失，回到 SLEEPING。

## 4. 状态内部字段

| 字段 | 含义 |
|---|---|
| `state` | SLEEPING / AWAKE / MUTED |
| `expires_at` | AWAKE 到期时间 |
| `wake_cooldown_until` | 关窗后的唤醒冷却 |
| `last_spoke_at` | 上次发言时间，用于 3s 发言冷却 |
| `daily_count` / `daily_day` | 当日主动条数，跨天自动清零 |
| `failures` / `active_ok` | 连续发送失败次数 / 该群主动消息权限是否可用 |
| `pass_count` | 窗口内连续 PASS 次数 |
| `hook_until` / `hook_used` | ABOUT 过渡句后的回钩（120s，只用一次） |
| `mute_until` / `mute_trigger_id` | 静默到期时间 / 触发静默的消息 id |
| `keyword_until` / `user_keyword_at` | 群级 20s / 用户级 20s 关键词冷却 |
| `recent_ids` | 最近消息 id，防重复处理 |

## 4.5 活跃期

唤醒后前 `ACTIVE_GRACE_SEC`（默认 180 秒）内，非 @ 消息不做指向/话题判定，直接回复；例外是 @ 了别人（退场）和明确静默词（静默）。之后回到策略。每次开窗/唤醒都会刷新活跃期起点。

`AWAKE` 下的非 @ 消息先过 5 秒防抖（`DEBOUNCE_SEC`）：同人新消息重置计时、他人消息只并入不重置；到期用拼接文本判定一次，窗口关闭则丢弃；@ 消息不参与防抖（立即回，批次保留）。

## 5. 退出原因对照表

| reason | 触发点 | 日志 |
|---|---|---|
| `timeout` | 窗口到期 | `presence exit ... reason=timeout` |
| `mention_other` | AWAKE 时有人 @ 了别人 | `presence exit ... reason=mention_other` |
| `model_left` | judge 判 SLEEP | `presence exit ... reason=model_left` |
| `pass_limit` | judge 连续 3 次 PASS（策略 PASS 不计） | `presence exit ... reason=pass_limit` |
| `daily_cap` | 日上限 | `presence exit ... reason=daily_cap` |
| `note_failure` | 主动消息发送失败 | `presence error ... code=...` |

判定过程本身看这两行：

```
presence judge   group=... action=reply|pass|sleep
presence decide  group=... state=awake action=in_window reason=rate|cooldown
```

## 6. 当前参数（.env 快照）

| 参数 | 值 | 作用 |
|---|---|---|
| `GROUP_PRESENCE_RATE` | 0.6 | 睡着时每条消息进入在场的概率 |
| `GROUP_PRESENCE_WINDOW_SEC` | 600 | AWAKE 窗口时长 |
| `GROUP_PRESENCE_RATE_IN_WINDOW` | 1.6 | 窗口内概率倍率（0.6×1.6≈0.96） |
| `GROUP_PRESENCE_REPLY_COOLDOWN_SEC` | 3 | 两次主动发言最小间隔 |
| `GROUP_PRESENCE_WAKE_COOLDOWN_SEC` | 300 | 关窗后多久才能再被唤醒 |
| `GROUP_PRESENCE_DAILY_ACTIVE` | 120 | 每群每日主动条数上限 |
| `GROUP_PRESENCE_MUTE_SEC` | 1800 | 静默时长 |
| `GROUP_PRESENCE_MUTE_WORDS` | 闭嘴,别说了,安静 | 静默触发词（须 @bot） |
| `GROUP_PRESENCE_KEYWORD_COOLDOWN_SEC` | 20 | 群级关键词冷却 |
| `GROUP_PRESENCE_KEYWORD_USER_COOLDOWN_SEC` | 20 | 用户级关键词冷却 |
| `GROUP_PRESENCE_KEYWORD_WINDOW_SEC` | 300 | ABOUT 窗口时长 |
| `GROUP_PRESENCE_HOOK_SEC` / `HOOK_RATE` | 120 / 1.0 | 过渡句后的回钩 |
| `GROUP_PRESENCE_JUDGE_ENABLED` | true | 窗口内三态判定开关 |
| `GROUP_PRESENCE_DEBOUNCE_SEC` | 5 | AWAKE 下防抖秒数，0 关闭 |
| `GROUP_PRESENCE_PASS_LIMIT` | 3 | 连续 PASS 多少次自动退场 |
| `GROUP_PRESENCE_JUDGE_CONTEXT_MESSAGES` | 8 | 判定喂多少条上下文 |

调参速查：

- 觉得**叫不应**：降 `KEYWORD_*_COOLDOWN`，或把 CALL 窗口继续保留。
- 觉得**话太多**：降 `RATE` 或 `RATE_IN_WINDOW`，或调大 `PASS_LIMIT` 之外的冷却。
- 觉得**退场太慢**：调小 `PASS_LIMIT`，或缩短 `WINDOW_SEC`。
- 觉得**刚关窗又被叫醒**：调大 `WAKE_COOLDOWN_SEC`。

## 8. 常见疑问

**Q：AWAKE 期间被 @ 会重置 10 分钟吗？**
不会。@ 只回一条，窗口仍按原来的 `expires_at` 到期。

**Q：窗口内被叫名字为什么没重新开窗？**
窗口内再命中名字会走 `keyword_awake`，交回 0-1，但带 `force`，所以一定回；不延长窗口。

**Q：为什么 bot 明明在窗口里却不回某条？**
按顺序可能被拦：发言冷却（3s）、judge 判了 PASS、日上限、不可接过滤，或那条 @ 了别人（直接退场）。

**Q：静默期间有人 @ 它，算解除吗？**
算。任意 @ 都能解除静默（触发静默的那条 ack 除外）。

**Q：重启会怎样？**
所有状态清零，回到 SLEEPING；静默也失效。
